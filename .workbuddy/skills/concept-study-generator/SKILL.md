# 概念学习资料生成器（concept-study-generator）

## 一、适用场景

当出现下面这类需求时使用本 Skill：

- 需要理解某个技术/理论概念，并产出一份**可以反复回看、可以交给别人检查**的学习资料
- 课程作业要求"学习某概念并说明个人理解"
- 想把一个模糊的名词变成"我能讲清楚、能举例子、知道边界在哪"的知识

## 二、不适用场景

出现以下情况请改用其他方式，不要硬套本 Skill：

- 需要**编写或调试具体代码** —— 本 Skill 只产出学习资料，不产出可运行程序
- 需要**实时数据**（今日股价、最新新闻）—— 本 Skill 依赖可引用的静态资料
- 概念本身**不存在可核查的公开来源**（如内部项目代号）—— 会触发来源校验失败

## 三、输入信息

调用时尽可能提供，缺失项按括号内规则处理：

| 输入项 | 是否必填 | 缺失时的处理 |
|---|---|---|
| `概念名` | 必填 | 无法生成，直接向用户追问 |
| `学科背景` | 选填 | 默认"计算机与人工智能通识" |
| `学习者基础` | 选填 | 默认"已掌握 Python 基础，未系统学过相关理论" |
| `资料用途` | 选填 | 默认"课程作业，需要可核查来源" |
| `输出路径` | 选填 | 默认 `learning-materials/<概念英文名小写连字符>.html` |

## 四、生成步骤

### 步骤 1：定位与界定（不要跳过）

先用一句话说清这个概念**解决什么问题、处于什么位置**。然后明确它的边界：它**不是**什么。
这两句写不出来，说明还没理解，应回到资料再读，而不是硬凑内容。

### 步骤 2：拆解核心机制

把概念拆成 3–5 个组成要素或运行步骤，要求：

- 每个要素能用**自己的话**一句话说清
- 要素之间有**明确的先后或依赖关系**，能画成一条流程
- 对每个要素追问一次"为什么需要它" —— 答不上来的要素要么删掉，要么说明是存疑项

### 步骤 3：设计应用场景

选**一个**具体场景，要求可感知、可复现：

- 写清输入是什么、经过概念中的哪几个要素、输出变成什么
- 给出具体的数值、文件名或操作步骤，不要写"某地某公司"这类空泛描述
- 说明**如果不用这个概念，同样的事会怎么变糟** —— 这是体现价值的关键

### 步骤 4：整理易混淆点

至少列 3 条，每条必须包含：

- 常见误解是什么
- 正确的说法是什么
- 为什么会错（多数混淆来自把"能力"当成"必然行为"，或把"相关"当成"因果"）

### 步骤 5：收集并核验资料来源

- 至少 3 条来源，优先学术论文、官方文档、一手技术博客
- **必须用工具实际访问验证**，返回 200 才可引用
- 访问不通的链接分两种情况：返回 404/域名不存在 = 链接无效，必须换掉；本机网络被封（超时/连接失败/地区限制）= 可保留，但要在资料里如实标注"本机无法核验"
- **严禁凭印象编造 URL、标题或作者**

### 步骤 6：出一份自测

3–5 道题，覆盖：机制理解、场景应用、边界判断。
至少 1 道是"看起来对但其实错"的判断题 —— 最能暴露真实理解程度。
答案折叠在 `<details>` 标签里。

### 步骤 7：生成 HTML 并自检

按下方输出结构生成单文件 HTML，然后**逐条跑一遍第八节的自检清单**。
任何一条不通过，修改后重新生成，不要直接交付。

## 五、输出结构

生成一个**自包含的 HTML 文件**（CSS 内联，不依赖外部资源），章节顺序固定：

```
1. 概念速览        —— 一句话定义 + 它不是什么 + 一句话个人理解
2. 学习目标        —— 3~4 条，读完后应该能做到什么
3. 核心问题        —— 2~3 个驱动性问题，后文要能回答
4. 核心机制        —— 3~5 个要素，附 Mermaid 或纯文本流程图
5. 应用场景        —— 一个具体场景，含输入/处理/输出与"不用它会怎样"
6. 易混淆点与边界  —— 至少 3 条，每条含误解/正解/为什么错
7. 自测题          —— 3~5 题，答案可折叠
8. 资料来源        —— 至少 3 条，含链接、核验状态、一句话说明该来源支撑哪部分
9. 我的疑问        —— 至少 1 条仍未搞懂的问题（没有疑问说明学得不够深）
```

排版要求：标题层级清晰、代码块与表格有边框、页面最大宽度控制在 900px 左右、中文正文行高 1.7。

## 六、资料来源要求

- **数量**：≥ 3 条，其中至少 1 条是一手资料（论文原文或官方文档）
- **核验**：逐条实际访问，在来源表中标注核验结果（`已核验 200` / `本机网络受限，未核验`）
- **禁止**：编造链接、编造标题、把二手博客当作原始出处、整段复制原文
- **引用方式**：在对应章节处用 `[1]` `[2]` 上标标注，文末来源表给出完整链接
- **个人解释**：概念解释必须是改写后的表达，可以引用观点但不得整段照搬

## 七、自检要求（交付前逐条确认）

- [ ] 一句话定义里没有出现"这个概念是……的一个概念"这类同义反复
- [ ] 核心机制的要素数量在 3–5 个之间，且每个都用自己的话写清楚了
- [ ] 应用场景包含具体输入与输出，不是空泛举例
- [ ] 易混淆点 ≥ 3 条，且每条都说清了"为什么会错"
- [ ] 自测题 ≥ 3 道，含至少 1 道陷阱判断题
- [ ] 来源 ≥ 3 条且全部实际访问验证过，无编造
- [ ] "我的疑问"非空
- [ ] HTML 能在浏览器直接打开，无外部依赖，无乱码
- [ ] 通读一遍：如果删掉所有来源链接，剩下的内容仍然是**我自己的理解**而非资料拼接

最后一条是底线。不满足就重写，不要交付。

## 八、调用示例

```
用 concept-study-generator 学习「向量数据库」
```

```
调用 concept-study-generator，概念：思维链（Chain-of-Thought）
学习者基础：刚学完 Transformer
输出路径：learning-materials/chain-of-thought.html
```

## 九、输出文件约定

- 默认路径：`learning-materials/<概念英文名小写连字符>.html`
- 例：`Agent` → `learning-materials/agent.html`；`大模型的上下文` → `learning-materials/llm-context.html`
- 生成后告知用户文件路径，并提示"请打开浏览器查看排版是否正常"

## 十、与其他资料的关系

若仓库中已有其他概念的学习资料（如 `learning-materials/` 下的文件），生成新资料时应：

- 检查是否已存在同概念文件，避免重复生成
- 若新概念与已有概念存在依赖或对比关系，在"易混淆点与边界"中主动交叉引用，并提示可更新 `concept-relationship` 关系说明文档
